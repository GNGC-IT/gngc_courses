We know how to let our player interact with things in the world just by walking around, but we can fairly easily give our player the ability to **interact with the mouse!**
It's not crazy hard, and once you have the basics, it's easy to build onto.
To let our user point-and-click on things in the world, we need to use **raycasts**

## What are RayCasts?

> [!NOTE] What is a RayCast?
> Imagine firing an invisible laser beam straight out from the center of your camera.
> A **RayCast3D** line-checks the 3D physics space along that beam and returns information about whatever object it hits (its distance, collision point, and the specific node hit).
> 2D Raycasts exist as well, and are also useful!
  

### How RayCast3D Works in Godot

1. **Origin**: Starts at the `RayCast3D` node's position (usually aligned with your camera).

2. **Target Position (`target_position`)**: Dictates how far and in what direction the laser shoots (e.g., `Vector3(0, 0, -3)` shoots 3 units directly forward in Godot's `-Z` direction).

3. **Collision Detection**: Every frame, Godot checks if the ray intersects with a physics body (`StaticBody3D`, `RigidBody3D`, etc.).

  So how are we going to do this?
  1. Add a raycast node to our Protocontroller
  2. Define an "interactable" object script (a Parent class!)
  3. Make a specific "interactable button" (a Child class!)
  4. Make a script that will let the player interact with objects

## Part 2-3 - Creating an "Interactable" object
So let's chat about what our player is going to want to do.
Do we want our player to click on buttons that change colour? Should they click on doors that open with animations? Should they change the setting on a light reflecting mirror? Or is it a kind of switch?

What we want to be able to do, is to make a script that informs all of these possible uses. So we're going to use ***Inheritance*** again.

Remember when we designed our State Machine states to have a **base** state class that everything else is built on? Same deal! We're going to make a script called **interactable**, and then we'll inherit from it for specific functions.

Take a look at my **interactable.gd** script:
```gdscript
extends StaticBody3D
class_name Interactable

# Base placeholder method — intended to be overridden by child classes
func interact():
    pass
    
```

And now, please enjoy my **interactable_button.gd** script!
```gdscript
extends Interactable
class_name ButtonInteractable

@onready var button_mesh = $CSGCylinder3D

@export var red_material: StandardMaterial3D
@export var green_material: StandardMaterial3D

var is_pressed: bool = false

func _ready():
    button_mesh.material = red_material

# Overriding the parent's interact() method
func interact():
    is_pressed = !is_pressed
    button_mesh.material = green_material if is_pressed else red_material
    
```

So the breakdown:
- Our base **interactable** class allows any **static body** that our player clicks on to be able to do *something*
	- We don't know what that something is yet, but basically our player wants to interact with it
- We can create any amount of variations on this class, where we add more variables, node references, functions, and we can put anything we like inside the **interact** function.

```gdscript

func _input(event):
    # Pressed "interact" button
    if event.is_action_pressed("click"):
        if is_colliding():
            var body = get_collider()
            if body is Interactable:
                body.interact()
```

## Part 6 - Let's make an activated platform!
![[platform_image.png]]
This is what I'm working with here! I have a platform that sinks into the floor.
I've added an AnimationPlayer to it, and created an animation called "move":
- The animation is 3  seconds long
- Changes the Y position from -5, to 0, then back to -5
![[platform_anim_settings.png]]

Now let's customise our button script a bit:
```gdscript
extends Interactable
class_name ButtonInteractable

@onready var button_mesh = $CSGCylinder3D/CSGSphere3D

@export var red_material: StandardMaterial3D
@export var green_material: StandardMaterial3D

@export var platform_anim : AnimationPlayer

var is_pressed: bool = false

func _ready():
	button_mesh.material = red_material
	platform_anim.animation_finished.connect(reset)

func interact():
	if not is_pressed:
		platform_anim.play("move")
	is_pressed = true
	button_mesh.material = green_material 

func reset(anim_name):
	is_pressed = false
	button_mesh.material = red_material 
```

The key differences are:
- We've added a reference to the platform's AnimationPlayer
	- Be sure to assign it in the editor!
- Inside our Interact function:
	- We're now checking to see if the button is pressed. (We don't want to play the animation if it's already playing)
	- We're telling it to
		- Play the animation
		- Change our *is_pressed* variable to True, so we know the animation is currently running
		- Change the button material to green
- We've also created a new Reset function
		- It changes the *is_pressed* back to False, so the button will work again
	- Also changes the button material back to red
	- Over in the Ready function, we're linking this function to the animator's "Animation Finished" signal, so it runs every time that signal fires!
