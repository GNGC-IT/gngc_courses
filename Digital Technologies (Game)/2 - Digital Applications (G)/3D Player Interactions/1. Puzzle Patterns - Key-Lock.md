Ok, so let's talk basic puzzles!
A Key-lock system is the most simple way to go, so let's make sure we have the understanding for that fully sorted.

>[!NOTE]+ What we are, and are not doing
>We're going to have the player walk over a key, and then a door will open
>- We're not going to have the player interact with the door directly, the door is just going to open when the player walks over the key
>- The key isn't going to be stored with the player at all, it's just going to trigger the door opening

So let's get all the basics in our level:
## A *DOOR* 
Obviously, we need a door; but some doors are just built better than others. Here's my tips to a nice door. Here's my end result, and then my guide:
![[Door.png]]
1. Make a wall with a CSG Box. 
	1. I've given mine a black material, and renamed it "Wall"
	2. Obviously, **turn collisions on for the wall**
2. Give it a child CSG
	1. I've used a Cylinder here, and set the Scale on it to 1.5 on the X, while keeping a scale of 1 on the Y and Z; this gives it the Arch! (I also bumped up the Sides to 12)
	2. The main thing is that you need to set the Operation on it to **subtraction**
	3. Rename this to "Hole"
3. Duplicate the "Hole" CSG
	1. On the new "Hole2", rename it to "Door", and change the Operation back to Union
	2. You probably want to give this one a different, unique, material

You should be able to check that this is working well enough, by clicking the visibilty ON and OFF on the door to make sure that it looks good!

## Animating the door
Look, we could just delete the door, but it's a bit lame. Let's animate it to open.
For this, I'm going to go for a Sci-Fi style lowering the door down.

Click on your Wall, and give it a new child node; you're looking for an **AnimationPlayer**
When you give it the AnimationPlayer, you will get the Animation tab and window at the bottom of the screen open.

I'm going to let a gif take over the demo for a second:
![[Door_anim_demo.gif]]
Ok, so the key moments in there:
- We create a new animation, call it "open"]
- Select the door, and then hit the Key next to the Position vector to set the Closed position
- Move the animation track up, and then change the door's position to the Open position, and hit the key again
- I wasn't quite happy with the speed, so I decided to change the length of the animation to 0.5 seconds, and move the second keyframe's position to match.
- Play the animation a couple times to make sure you're happy!


## Making a Key
Ok, so in this, I'm assuming a boring CSG for the key, rather than an actual "key-shaped object". If you want to get fancy, please do!

Here's the step-by-step
1. Add an **Area3D**. 
	- We want our key to see when our player's body moves into it's area, so an Area3D is the right move here
	- Rename it "Key"
2. Add a CSG of your choice
	- Today, I'm feeling like giving the player some hints, so I've gone with a Cylinder, re-scaled to look like the same shape as our door!
	- Make sure you give it a material too, you could go with the same settings as your door, but I feel like gold. You can take the settings for my deafult gold here -> [[Materials 1 - The Basics#Handy Basic Material Reference]]
3. Don't forget the collision shape!
	- Honestly, you should probably just use a box collider, since it really doesn't need to be that specific!

## Scripting the Key
So now we just need to script the key!
It's pretty basic, so let's take a look at the script I'm using:
```gdscript
extends Area3D

@export var door_anim : AnimationPlayer

func _on_body_entered(body):
	if body.name == "ProtoController":
		door_anim.play("open")

```

A couple to-dos around it. Once the script is saved and assigned to the key:
1. Assign the Door's Animation Player node as the "Door Anim" variable in the inspector
2. Don't forget to select the Key, go over to Signals, and double click the body_entered signal and make sure it gets linked to the key.gd script!
3. If you changed the name of the ProtoController in the scene, make sure you change the name we're looking for in the script too!
